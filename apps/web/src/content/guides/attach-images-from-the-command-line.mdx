<section class="lead" id="short-answer">

## Short answer <a class="anchor" href="#short-answer" aria-label="Link to this section">#</a>

If you have write access, a personal token, and one image or video for a PR that already exists,
use `gh pr comment --attach`. It's built into gh 2.99 and later. Reach for something else when:

- The token is an Actions `GITHUB_TOKEN` or a GitHub App token.
- The file isn't an image or video.
- You don't have write access to the repository.
- The pull request doesn't exist yet.
- The repository is on GitHub Enterprise Server.

</section>

<section id="gh-attach">

## `gh --attach` <a class="anchor" href="#gh-attach" aria-label="Link to this section">#</a>

`gh pr comment`, `gh issue comment`, and related commands take `--attach` for images and video, up
to 50 files per command. Known gaps:

- Actions and GitHub App installation tokens get a 404 from the upload endpoint
  ([cli/cli#14309](https://github.com/cli/cli/issues/14309)).
- It requires write access, even though the web editor doesn't
  ([cli/cli#14302](https://github.com/cli/cli/issues/14302)).
- No Markdown or other file types ([cli/cli#14407](https://github.com/cli/cli/issues/14407)).
- No GitHub Enterprise Server support ([cli/cli#14335](https://github.com/cli/cli/issues/14335)).

Copilot `ghu_` user tokens were refused by gh until
[cli/cli#14516](https://github.com/cli/cli/pull/14516), merged September 25, 2026.

</section>

<section id="assets-branch">

## Assets branch <a class="anchor" href="#assets-branch" aria-label="Link to this section">#</a>

Commit images to a dedicated branch and link to them from the comment. It works with any token that
can push, including the Actions token. The images stay in your repository's history.

</section>

<section id="uploads">

## uploads CLI <a class="anchor" href="#uploads" aria-label="Link to this section">#</a>

The uploads CLI hosts files on its own storage with its own token and links them from the PR. It
doesn't call GitHub's upload endpoint, so the token and file-type gaps above don't apply. Files get
stable URLs, and you can stage them on a branch before the PR opens.

```bash
uploads put ./after.png --pr 123
```

The tradeoff: files live outside GitHub and are public to anyone with the URL.
