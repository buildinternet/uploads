<section class="lead" id="how">

## How it works <a class="anchor" href="#how" aria-label="Link to this section">#</a>

Agents that run in a hosted sandbox often can't install the uploads CLI. The hosted MCP server gives
them the same uploads over a URL. With it, a cloud agent can:

- Upload screenshots, recordings, and files to a pull request.
- Stage files on a branch before the PR exists.
- Get back a public URL and Markdown for anything it uploads.

</section>

<section id="connect">

## Connect the MCP server <a class="anchor" href="#connect" aria-label="Link to this section">#</a>

Add this server URL to your agent's MCP settings:

```text
https://agents.uploads.sh/mcp
```

The agent signs in with OAuth the first time it connects. You can also send a workspace token as
`Authorization: Bearer up_…` from [your account settings](/account/developers#workspace-tokens).

</section>

<section id="app">

## Install the GitHub App <a class="anchor" href="#app" aria-label="Link to this section">#</a>

Install the [uploads GitHub App](/docs/github-app) on the repository. It posts the attachments
comment for uploads made through the hosted server.

</section>

<section id="upload">

## Upload from the agent <a class="anchor" href="#upload" aria-label="Link to this section">#</a>

The agent calls the `put` tool with the file and the pull request:

```json title="put" frame="code"
{
  "filename": "settings-after.png",
  "contentBase64": "iVBORw0KGgo…",
  "repo": "acme/web",
  "pr": 12,
  "state": "after"
}
```

Pass `contentUrl` instead of `contentBase64` when the file is already at a public HTTPS URL. Pass
`branch` instead of `pr` to stage it before the PR opens.
