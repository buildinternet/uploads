<section class="lead" id="why">

## Why a template <a class="anchor" href="#why" aria-label="Link to this section">#</a>

A pull request template reminds every author, human or agent, to show what a UI change looks like.
With a screenshots section and one line in your agent's instructions, you get:

- A before and after on every visual change.
- Screenshots staged while the work happens, not reconstructed at review time.
- One place reviewers know to look.

</section>

<section id="template">

## Add the template <a class="anchor" href="#template" aria-label="Link to this section">#</a>

```md title=".github/pull_request_template.md" frame="code"
## What changed

## Screenshots
<!-- UI changes: show a before and an after.
     Captures tagged --state before / --state after are paired
     in the attachments comment below. -->

## How to test
```

GitHub pre-fills pull requests opened on the web with this file. Tools that create PRs from the
command line may skip it, which is why the next step matters.

</section>

<section id="agent">

## Tell your agent <a class="anchor" href="#agent" aria-label="Link to this section">#</a>

Agents don't always read the template, so add this to `AGENTS.md`, `CLAUDE.md`, or whatever your
agent reads:

```md title="AGENTS.md" frame="code"
## Pull requests
Fill in .github/pull_request_template.md when you open a PR.
For UI changes, capture before you edit and again after:

  uploads put ./before.png --meta path=/route --state before
  uploads put ./after.png --meta path=/route --state after

After opening the PR, run `uploads attach --promote`.
```

The two captures appear side by side in the pull request's attachments comment.
