## How it works <a class="anchor" href="#how" aria-label="Link to this section">#</a>

A coding agent can open a pull request, but it can't drag a screenshot into GitHub. With the uploads
CLI and its agent skills, the agent:

- Captures or saves a screenshot after each visual change.
- Stages it on the branch before the PR exists.
- Posts everything to one attachments comment when the PR opens.

The workflow is the same for every agent. Only the install step differs.

</section>

## Install <a class="anchor" href="#install" aria-label="Link to this section">#</a>

Install the CLI, sign in once, and add the skills and MCP server to every agent on your machine:

```bash
npm install -g @buildinternet/uploads && uploads login
```

```bash
uploads install
```

Then finish setup for your agent:

<Tabs syncKey="agent-runtime">
  <TabItem label="Claude Code">

Install the plugin to add the reminder that runs before the agent opens a PR:

```text
/plugin marketplace add buildinternet/uploads
```

```text
/plugin install uploads@uploads
```

  </TabItem>
  <TabItem label="Codex">

Enable the uploads plugin for the reminder, then open `/hooks` once and trust the hook if Codex
asks.

  </TabItem>
  <TabItem label="Grok">

Nothing else. `uploads install` added the MCP server and the reminder.

  </TabItem>
  <TabItem label="Cursor">

`uploads install` added the reminder. Add the MCP server in Cursor's MCP settings, or in
`.cursor/mcp.json`:

```json title=".cursor/mcp.json" frame="code"
{
  "mcpServers": {
    "uploads": { "url": "https://agents.uploads.sh/mcp" }
  }
}
```

Cursor cloud agents can also post their own screenshots to the PR. With the
[GitHub App](/docs/github-app#ingest) installed, uploads imports those into your workspace
automatically.

  </TabItem>
  <TabItem label="OpenCode">

Register the MCP server:

```bash
opencode mcp add uploads --url https://agents.uploads.sh/mcp
```

  </TabItem>
</Tabs>

## Tell the agent when to capture <a class="anchor" href="#instructions" aria-label="Link to this section">#</a>

Add this to your project's instructions file: `AGENTS.md`, `CLAUDE.md`, `.cursor/rules`, or whatever
your agent reads.

```md title="AGENTS.md" frame="code"
## Screenshots
When a change is visible (UI, layout, styling), capture it as you go.
Don't wait for the PR. After each meaningful visual change:

  uploads put ./shot.png --meta path=/route --state after

On a branch, that stages the file for the PR. After opening the PR, run
`uploads attach --promote` to post everything staged. It's safe to run
even if the GitHub App already posted them.
```

With the [GitHub App](/docs/github-app) installed, staged files are posted when the PR opens, with
no extra command.

<section id="capture">

## Capture a page <a class="anchor" href="#capture" aria-label="Link to this section">#</a>

When the agent can reach the page, `uploads screenshot` renders it and hosts the image in one step,
so there's no file to hand off:

```bash
uploads screenshot http://localhost:3000 --pr 123
```
