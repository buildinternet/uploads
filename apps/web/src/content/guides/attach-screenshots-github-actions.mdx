<section class="lead" id="why">

## Why `gh --attach` fails in CI <a class="anchor" href="#why" aria-label="Link to this section">#</a>

`gh pr comment --attach` uploads through GitHub's attachment endpoint. That endpoint rejects the
Actions `GITHUB_TOKEN` and GitHub App installation tokens with a 404, even when the token can write
to the repository ([cli/cli#14309](https://github.com/cli/cli/issues/14309)). A workflow can still
comment. It can't upload.

The uploads CLI hosts the file with its own token and puts the image link in the comment, so the
workflow never calls GitHub's upload endpoint. With it, a CI job can:

- Post screenshots from a Playwright or Cypress run to the pull request.
- Attach non-image artifacts, like a test report or a log, to the same comment.
- Update one comment on each run instead of adding a new one.

</section>

<section id="setup">

## Set up the token <a class="anchor" href="#setup" aria-label="Link to this section">#</a>

Create a token for the workflow in [your account settings](/account/developers#workspace-tokens),
under **API Tokens**:

1. Pick the workspace, and give the token a label such as `ci`.
2. Set access to **Read & write**, and choose an expiry.
3. Copy the token. It starts with `up_<workspace>_`.

Save it as a repository secret named `UPLOADS_TOKEN`. The CLI reads the token and its workspace from
that variable.

<div class="note">
  The token belongs to the member who creates it, and files it uploads are attributed to them.
  Revoke it on the same settings page.
</div>

</section>

<section id="workflow">

## Add the workflow step <a class="anchor" href="#workflow" aria-label="Link to this section">#</a>

Add a step after the job that writes your screenshots:

```yaml title=".github/workflows/screenshots.yml" frame="code"
on: pull_request

permissions:
  contents: read
  pull-requests: write

jobs:
  screenshots:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      # …build the app and write screenshots to ./shots
      - run: npm install -g @buildinternet/uploads
      - run: uploads put ./shots/*.png --pr ${{ github.event.pull_request.number }}
        env:
          UPLOADS_TOKEN: ${{ secrets.UPLOADS_TOKEN }}
          GH_TOKEN: ${{ github.token }}
```

The files get stable URLs keyed to the pull request. The attachments comment posts as
`uploads-sh[bot]` when the [GitHub App](/docs/github-app) is installed. Without the App, the CLI
posts the comment with `gh`, which uses `GH_TOKEN`. Commenting with the Actions token works. Only
the upload is blocked.

  Want a screenshot of a URL without a test runner? Use <code>uploads screenshot</code> —

</div>

<section id="other-options">

## Other options <a class="anchor" href="#other-options" aria-label="Link to this section">#</a>

Without uploads, the usual workaround is to commit images to an assets branch and link to them. It
works with the Actions token, but the images stay in your git history.

For a side-by-side, see [ways to attach images from the command line](/guides/attach-images-from-the-command-line).
