<section class="lead" id="what">

## What a feed is <a class="anchor" href="#what" aria-label="Link to this section">#</a>

A feed is a live public page of screenshots already tagged with a GitHub repo. With a feed you can:

- Share the latest shots for a repo behind one `/c/<id>` URL.
- Scope that same feed to one pull request or issue.
- Open one shot at `/c/<id>/<item>` and page through the set.
- Filter by page path (the same `path` metadata `uploads find` uses).

It is the same product either way — one extra filter. New tagged screenshots appear automatically. A
[gallery](/docs/galleries) is a curated set you add by hand.

Anyone who knows the URL can view the feed. GitHub repository visibility does not restrict it.

</section>

<section id="create">

## Create a feed <a class="anchor" href="#create" aria-label="Link to this section">#</a>

Create a repo-wide feed. This prints its public URL. Pass `owner/repo` or `--repo`. Omit both and
the CLI uses the current git remote. Two different repos get two feeds:

```bash
uploads feed create owner/repo
uploads feed create --repo owner/repo
```

Creating the same scope again returns the existing URL.

<div class="pointer">
  Want only one pull request? Add <code>--pr</code>, or pass <code>--github</code> with
  <code>owner/repo#123</code> or a GitHub URL. <code>--issue</code> does the same for an issue.
  Optional <code>--path</code> keeps the feed to one page path.
</div>

Open an existing feed with `uploads feed show`.

<div class="note">
  From a hosted agent (no local CLI), call MCP <code>feed_create</code> with <code>repo</code>, plus
  <code>pr</code> when the feed should stay on one pull request. <code>github</code> alone can
  supply both. <code>feed_get</code> returns the current shots and the public URL.
</div>

</section>

<section id="pager">

## Page through the set <a class="anchor" href="#pager" aria-label="Link to this section">#</a>

Each shot has its own page at `/c/<id>/<item>` — previous / next, and a 1 of N count. The feed
list links into that pager. Older `/feed/…` links redirect there.

Syncing the managed PR comment creates the PR-scoped feed if it does not exist yet (the same
idempotent create as `uploads feed create --repo … --pr …`). Each image in that comment then links
to its feed item page. The `<img>` still loads from the embed URL.

Standalone `/f/…` pages stay for one-off shares. Curated galleries are unchanged.

</section>

<section id="when">

## Gallery, repo, or PR <a class="anchor" href="#when" aria-label="Link to this section">#</a>

- **Gallery** — you pick and order the files. See [Galleries](/docs/galleries).
- **Repo feed** — the latest screenshots across a repo.
- **PR feed** — the same feed, scoped to one pull request.

</section>
