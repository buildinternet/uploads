<section class="lead" id="attach">

## Attach files to a PR <a class="anchor" href="#attach" aria-label="Link to this section">#</a>

With a pull request open, run `attach` from its branch:

```bash
uploads attach ./screenshot.png
```

The files land on the PR as one managed comment:

<GhComment />

Run `attach` again and the same comment updates in place.

`attach` finds the repo and PR through the `gh` CLI. To target something else, add `--pr <n>` or
`--issue <n>`, plus `--repo owner/name` for another repo.

</section>

<section id="staging">

## Stage before a PR exists <a class="anchor" href="#staging" aria-label="Link to this section">#</a>

No PR yet? Upload with `put`. On any branch other than the default, it stages the file for that
branch's future PR:

```bash
uploads put ./after.png
```

[`uploads screenshot`](/docs/capture) stages the same way. When the PR opens, staged files move
onto it: right away with the [GitHub App](/docs/github-app#staging), or on your next
`uploads attach`.

<div class="pointer">
  Staging several files at once? Use `uploads attach --branch`.
</div>

To see what's queued, run `uploads staged`:

```ansi title="uploads staged"
$ uploads staged
after.webp  94.2 KB  staged 2026-07-22T14:00:00Z  https://storage.uploads.sh/gh/you/app/branch/feat-nav/after.webp
binding: self — these auto-attach when this branch's PR opens
once the PR exists: uploads attach --promote
```

If `binding` shows anything other than `self`, the files won't attach on their own. See
[GitHub App: staging before a PR exists](/docs/github-app#staging) to fix it.

Staged the wrong branch, or the files are leftover? `uploads unstage --branch <name>`
marks them unstaged. The file and its URL stay. They drop out of `uploads staged`
and out of auto-promotion. Add `--dry-run` to preview. Pass object keys instead of
`--branch` to unstage those objects only.

</section>

<section id="put">

## Get a URL for a file <a class="anchor" href="#put" aria-label="Link to this section">#</a>

`put` uploads a file and prints a public URL and Markdown you can paste anywhere:

```ansi title="uploads put"
$ uploads put ./shot.png
>> optimized 411.5 KB → 94.2 KB (shot.webp)
URL: https://storage.uploads.sh/screenshots/app/2026-07-12/shot-9f2c1a.webp
MARKDOWN: ![shot.png](https://storage.uploads.sh/screenshots/app/2026-07-12/shot-9f2c1a.webp)
```

Common flags:

- `--pr <n>` also posts the file to that PR.
- `--url <url>` uploads a file from the web instead of a local path.
- `--no-optimize` keeps the original bytes.
- `--meta path=/settings` names the page a screenshot shows. The comment shows it under the image.
- `--screen "Chat"` names a mobile or desktop app screen that has no page path. The comment shows it
  under the image too, next to the path if both are set.
- `--caption "Empty state after deleting the last project"` says what the shot shows, in up to 140
  characters. The comment shows it as plain text under the image, before the other labels.

`put` converts images to WebP and strips their EXIF data. It keeps a few capture details, like
viewport and device, and shows them on the file's public page. See
[Good to know](/docs/reference#good-to-know) for what's kept and how to turn it off.

</section>

<section id="before-after">

## Pair a before and after <a class="anchor" href="#before-after" aria-label="Link to this section">#</a>

Tag two images or two videos with `--state` and they render side by side in a Before and After table
in the comment:

```bash
uploads put ./hero-before.webp --state before
uploads put ./hero-after.webp --state after
```

If one comment has several pairs, give each pair the same `--meta path=<page>` or `--screen <name>`
value so they match up. Without either, files pair by name, so `hero-before.webp` matches `hero-after.webp`.
Several pairs share one table, a row each. A file with no before shows on its own, as usual.

A repo can [require a before and after](/docs/require-screenshots#more) on every pull request that
changes UI files.

</section>
