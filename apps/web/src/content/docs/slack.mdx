## What it does <a class="anchor" href="#what-it-does" aria-label="Link to this section">#</a>

The uploads.sh Slack app turns uploads.sh links into previews. With it in your workspace:

- A [file link](/docs/attach-pull-request-images) shows its image, the pull request or issue it
  belongs to, and its type, size, and upload time.
- A [live link](/docs/feeds) shows the pull request title and state, the latest screenshot, and
  how many files it holds.
- A [gallery](/docs/galleries) link shows its title, description, and cover image.

Connect your account, and the app also messages you when an upload is
[held for review](/docs/agents#held-uploads). You can approve it from the message.

Once search is on, you can also [mention the app with a question](#ask) and it answers in the
thread with the files it finds.

</section>

## Add it to Slack <a class="anchor" href="#install" aria-label="Link to this section">#</a>

Anyone who can install apps in a Slack workspace can add it:

<p>
  <a href="https://agents.uploads.sh/slack/install">
    <img
      alt="Add to Slack"
      height="40"
      width="139"
      src="https://platform.slack-edge.com/img/add_to_slack.png"
      srcset="https://platform.slack-edge.com/img/add_to_slack.png 1x, https://platform.slack-edge.com/img/add_to_slack@2x.png 2x"
    />
  </a>
</p>

Slack asks for these permissions:

| Permission          | What the app does with it                                                   |
| ------------------- | --------------------------------------------------------------------------- |
| `links:read`        | Sees uploads.sh links in messages. It reads only the link, not the message. |
| `links:write`       | Adds the preview to an uploads.sh link.                                     |
| `users:read`        | Reads your Slack name for the connect page, and checks who may search.      |
| `chat:write`        | Sends held-upload messages and answers in threads.                          |
| `im:write`          | Opens the direct message between you and the app.                           |
| `commands`          | Adds `/uploads search`.                                                     |
| `app_mentions:read` | Sees messages that mention the app.                                         |
| `channels:history`  | Reads the thread the app was mentioned in, in public channels.              |
| `groups:history`    | Reads the thread the app was mentioned in, in private channels.             |
| `reactions:write`   | Adds 👀 to your message while it works on an answer.                        |

The app reads a thread only when someone mentions it there, and never reads your Slack files.
Post an uploads.sh link to see a preview.

You can also find **Add to Slack** under **Settings → Slack** in each workspace on uploads.sh.

When the app gains a feature that needs a new permission, Slack doesn't grant it on its own. The
app's **Home** tab, and your Slack workspace under **Slack** in
[account settings](/account/profile#slack), show **Update permissions**. Press it and approve the
new permission on Slack's page. Until then, the feature that needs it is off in that workspace;
everything else keeps working.

</section>

<section id="connect">

## Connect your account <a class="anchor" href="#connect" aria-label="Link to this section">#</a>

Open the app's **Home** tab in Slack and press **Connect uploads.sh**. Sign in to uploads.sh if
asked. The page names the Slack account it's about to connect; confirm only if it's yours. The
link ties your Slack account in that workspace to your uploads.sh account.

Previews work without connecting. The link is for features that act on your behalf. To undo it,
press **Disconnect** on the same Home tab, or under **Slack** in
[account settings](/account/profile#slack).

Connecting doesn't add you to a workspace and doesn't use a seat. It only records which
uploads.sh account is yours. On the free plan, the member limit still applies when someone joins
a workspace, and connecting Slack doesn't change it.

</section>

<section id="held-uploads">

## Held-upload messages <a class="anchor" href="#held-uploads" aria-label="Link to this section">#</a>

When an upload is [held for review](/docs/agents#held-uploads) because it may show a secret or
personal information, the app sends a direct message. It names the file, the workspace, and why
the file is held, and it has two buttons:

- **Approve** puts the file back at its public link, the same as `uploads approve`. It acts as
  your connected uploads.sh account, so you must be a member of the workspace.
- **Keep held** leaves the file held. You can still approve it later from the file's page or the CLI.

Who gets the message:

- The person who uploaded the file, when uploads.sh knows who that is.
- Otherwise, the workspace's admins and owners.

Each person must have connected Slack. To stop these messages, turn off **Message me in Slack when
an upload is held for review** under **Slack** in [account settings](/account/profile#slack).
Messages arrive in the app's **Messages** tab in Slack.

</section>

<section id="search">

## Search from Slack <a class="anchor" href="#search" aria-label="Link to this section">#</a>

Find a workspace's public files by name without leaving Slack:

```
/uploads search login
```

The reply shows the five newest files whose name or folder matches, with a thumbnail for images.
Only you can see it. Pick a file from **Share a file to the channel** under the results to post it
for everyone.

A workspace admin or owner turns search on. In uploads.sh, open the workspace's **Settings →
Slack** page and switch on the Slack workspace under **Search from Slack**. It's listed once you've
[connected your account](#connect) there.

- Every full member of that Slack workspace can search, whether or not they connected an account.
- Guests and people from other organizations in shared channels can't.
- Results include only files the public share page would show. Private and held files never
  appear.

</section>

<section id="ask">

## Ask in a thread <a class="anchor" href="#ask" aria-label="Link to this section">#</a>

Mention the app with a question, in a channel it's in:

```
@uploads.sh do we have any recent screenshots from settings?
```

It answers in the thread with a sentence or two and the files that fit. It searches by name and
by what the [AI labels](/docs/agents#experimental-ai-tags) say a file shows (the kind of file, the screen,
and the device), and looks at the images before it answers. Mention it again in the same thread
to narrow the answer, for example `@uploads.sh just the mobile ones`. It reads the thread first,
so the follow-up builds on its last answer. Replies that don't mention it get no answer. Answers
are limited each day (UTC) on the free plan, with more on [Pro](/docs/limits#plans); a Slack workspace
connected to several uploads.sh workspaces gets the highest plan among them. Past the limit the app
says so until the next day.

It follows the same rules as [search](#search): a workspace admin turns it on, only full members
get an answer, and it finds only public files in the uploads.sh workspaces connected to that Slack
workspace, never any other workspace.

</section>

<section id="privacy">

## What a preview shows <a class="anchor" href="#privacy" aria-label="Link to this section">#</a>

A preview shows only what the public share page shows. The app reads the same public endpoints
the share pages use, so private, held, and deleted files get no preview.

<div class="note">
  Previews are visible to everyone in the channel. Post a link to a private file only where you'd
  share the file itself.
</div>

</section>
