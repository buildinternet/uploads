<section class="lead" id="what">

## What a gallery is <a class="anchor" href="#what" aria-label="Link to this section">#</a>

A gallery is an ordered set of media behind one public link, so you can share a whole batch of shots
as they're captured instead of one URL per file. Each gallery has a public page at `/g/<id>`.

A gallery is curated: it holds only the files you add, in the order you choose.

<div class="pointer">
  Want screenshots to collect on their own instead? Use a <a href="/docs/feeds">change feed</a> —
  <a href="#when">compare the two <span class="go">→</span></a>.
</div>

</section>

<section id="workflow">

## CLI workflow <a class="anchor" href="#workflow" aria-label="Link to this section">#</a>

Create a gallery — this prints its id:

```bash
uploads gallery create --title "Release screenshots"
```

Then add files to it, passing that id to `--gallery`:

```bash
uploads put ./shot.png --gallery <id>
```

The public page at `/g/<id>` updates as items are added.

</section>

<section id="linking">

## Link to a PR or issue <a class="anchor" href="#linking" aria-label="Link to this section">#</a>

Optional — this is metadata only, the gallery stays public at the same `/g/<id>` URL:

```bash
uploads gallery link <id> --github owner/repo#123
```

</section>

<section id="when">

## Gallery or feed <a class="anchor" href="#when" aria-label="Link to this section">#</a>

Use a gallery when you want to choose what people see. Use a [change feed](/docs/feeds) when you
want to follow what changes.

| | Gallery | Change feed |
| --- | --- | --- |
| **What's in it** | Only the files you add | Every screenshot tagged with the repo, or one PR or issue |
| **Order** | The order you choose | Newest first |
| **Upkeep** | Add each file with `--gallery` | None. New shots appear on their own. |
| **Use it for** | A release, demo, or review set | Following a repo or PR as it changes |

</section>
