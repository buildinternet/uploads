<section class="lead" id="install">

## Install <a class="anchor" href="#install" aria-label="Link to this section">#</a>

`uploads install` finds your agent runtime and adds the agent skills and the hosted MCP server:

```bash
uploads install
```

<div class="pointer">
  Using Claude Code or Codex? [Install the plugin](#plugin) instead.
</div>

### Or set up by hand

Add the skills:

```bash
npx skills add buildinternet/uploads
```

Then register the MCP server with your runtime:

<Tabs syncKey="agent-runtime">
  <TabItem label="Claude Code">

```bash
claude mcp add --transport http uploads https://agents.uploads.sh/mcp
```

  </TabItem>
  <TabItem label="Codex">

```bash
codex mcp add uploads --url https://agents.uploads.sh/mcp
```

  </TabItem>
  <TabItem label="Cursor">

Add it in Cursor's MCP settings, or in `.cursor/mcp.json`:

```json title=".cursor/mcp.json" frame="code"
{
  "mcpServers": {
    "uploads": { "url": "https://agents.uploads.sh/mcp" }
  }
}
```

  </TabItem>
  <TabItem label="OpenCode">

```bash
opencode mcp add uploads --url https://agents.uploads.sh/mcp
```

  </TabItem>
</Tabs>

<section id="plugin">

## Claude Code & Codex plugins <a class="anchor" href="#plugin" aria-label="Link to this section">#</a>

The plugin bundles the skills, the MCP server, the [pre-PR reminder](#pre-pr-reminder), and, in
Claude Code, the [staged media band](#staged-band). In
Claude Code, add the marketplace, then install:

```text
/plugin marketplace add buildinternet/uploads
```

```text
/plugin install uploads@uploads
```

Codex loads the same repo as a plugin. After you enable it, open `/hooks` once and trust the hook
if Codex asks.

The reminder hook calls the `uploads` CLI, so install it and run `uploads login` once.

</section>

<section id="instructions-file">

## Tell the agent to capture as it works <a class="anchor" href="#instructions-file" aria-label="Link to this section">#</a>

Add a block like this to your project's instructions file: `AGENTS.md`, `CLAUDE.md`,
`.cursor/rules`, or whatever your runtime reads.

```md title="AGENTS.md" frame="code"
## Screenshots
When a change is visible (UI, layout, styling), capture it as you go.
Don't wait for the PR. After each meaningful visual change:

  uploads put ./shot.png --meta path=/route --state after

On a branch, that stages the file for the PR. After opening the PR, run
`uploads attach --promote` to post everything staged. It's safe to run
even if the GitHub App already posted them.
```

For how staging works, see [Stage before a PR exists](/docs/attach-pull-request-images#staging).

<div class="note">
  Want the guided version? The [agent walkthrough](/github-screenshots) takes a coding agent from
  install to a first staged before/after.
</div>

</section>

<section id="pre-pr-reminder">

## Pre-PR screenshot reminder <a class="anchor" href="#pre-pr-reminder" aria-label="Link to this section">#</a>

Before `gh pr create`, the reminder hook nudges the agent if the branch touches UI files and
nothing is staged. It ignores files already promoted to a PR and never blocks the PR. Turn it off
with `UPLOADS_HOOK_DISABLE=1`.

When files are staged, the reminder checks whether the repo is linked to your workspace. If it is,
the reminder says the files attach automatically when the PR opens. If the link is missing or
unknown, it suggests `uploads attach --promote`. If the repo is linked to another workspace, it says
the files won't attach from here.

- **Claude Code and Codex:** included in the [plugin](#plugin).
- **Grok and Cursor:** `uploads install` adds it when those tools are installed.

</section>

<section id="staged-band">

## Staged media band <a class="anchor" href="#staged-band" aria-label="Link to this section">#</a>

In Claude Code 2.1.287 and later, the plugin adds a band above the prompt that shows what is staged
for the current branch. It draws in the terminal and in the Desktop app's Code tab. Older versions
load the rest of the plugin and skip the band.

- **Collapsed:** a line like "N uploads waiting for a PR on `<branch>` · attaches when it opens".
- **Expanded:** press ▸ for one row per staged file. A before/after pair shares one row. Each half
  links to its uploads.sh file page, and a dash marks a missing half. Claude Code's own `[-]`
  collapses the band.

After `gh pr create` opens a PR, the plugin attaches the staged files for you. If the repo is linked
to your workspace, the GitHub App attaches them and the band reports it. Otherwise the plugin runs
`uploads attach --promote` for that PR's branch.

To turn the automatic attach off, clear **Attach staged files on gh pr create** in `/plugin`. The
band then only reports what is waiting.

<div class="note">
  The band runs the local `uploads` CLI and `gh pr view`, each with its own sign-in. Without the CLI
  it does nothing. Hosted MCP, Codex, and Cursor setups don't get the band.
</div>

</section>

<section id="skill-vs-mcp">

## Skill vs. MCP <a class="anchor" href="#skill-vs-mcp" aria-label="Link to this section">#</a>

The **skills** teach the agent when to capture and which `uploads` command to run. They need the
CLI.

The **MCP server** gives the agent upload tools directly. There are two:

| Server                                  | Use it when                     | Differences                                                                                                  |
| --------------------------------------- | ------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| Local, `uploads mcp`                    | The agent runs on your machine  | Same tools as the CLI, including `attach`.                                                                   |
| Hosted, `https://agents.uploads.sh/mcp` | The agent has no local checkout | No `attach` and no git defaults. Pass `repo` and `branch` to `put`, then call `promote` once the PR exists. |

To use the local server instead of the hosted one:

<Tabs syncKey="agent-runtime">
  <TabItem label="Claude Code">

```bash
claude mcp add uploads -- uploads mcp
```

  </TabItem>
  <TabItem label="Codex">

```bash
codex mcp add uploads -- uploads mcp
```

  </TabItem>
</Tabs>

<section id="experimental-ai-tags">

## Experimental: AI labels <a class="anchor" href="#experimental-ai-tags" aria-label="Link to this section">#</a>

<div class="note">
  Experimental and **off by default**. The uploads.sh team turns it on per workspace. To try it,
  open an issue on [the GitHub repo](https://github.com/buildinternet/uploads).
</div>

When it's on, uploads.sh labels each file shortly after it's uploaded. The labels never replace a
`path` or `state` you set, and a labeling error never fails the upload. A label it isn't confident
about is left off.

| Key             | Values                                                                                                                                                |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ai.kind`       | `screenshot` `photo` `diagram` `document` `code` `ui` `other`                                                                                         |
| `ai.surface`    | `mobile` `desktop` `tablet` `unknown`                                                                                                                 |
| `ai.screen`     | `login` `signup` `settings` `profile` `dashboard` `analytics` `list` `detail` `form` `search` `modal` `onboarding` `empty` `error` `checkout` `other` |
| `ai.tags`       | Up to five kebab-case labels (raster images under 512 KiB)                                                                                            |
| `ai.summary`    | One short sentence (raster images under 512 KiB)                                                                                                      |
| `ai.classifier` | The labeler version, currently `v3`                                                                                                                   |

Labels aren't in the upload's response. Read them afterward, or search by them:

```ansi
uploads meta get <key>          # one file's labels
uploads find ai.screen=login    # files with a label
```

From an MCP client, use `get_metadata` and `find_files`. Clients can't set or delete `ai.*` keys.

</section>
